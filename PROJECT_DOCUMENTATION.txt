1. PROJECT OVERVIEW
================================================================================

1.1 Problem Statement

Generative AI (Large Language Models) can now produce highly convincing phishing
messages with perfect grammar, professional tone, and sophisticated social
engineering techniques. Traditional phishing detection methods that rely on
keyword matching, URL blacklists, or rule-based heuristics are ineffective
against AI-generated phishing because:

  - AI-generated messages lack the grammatical errors of traditional phishing
  - They use context-appropriate language that mimics legitimate communications
  - They employ psychological manipulation (authority, urgency, fear) at a
    sophisticated level
  - They can bypass spam filters by avoiding known malicious patterns

The Nigerian financial sector is particularly vulnerable due to:
  - High mobile money adoption (Moniepoint, PalmPay, Opay, Kuda)
  - Widespread use of USSD banking (*737#)
  - Common social engineering themes (BVN, NIN, CBN directives)
  - Limited cybersecurity awareness infrastructure

1.2 Solution

This project implements a six-layer semantic analysis framework using:

  Layer 1 - Input: Accept emails, SMS, and bank notifications
  Layer 2 - Preprocessing: Clean, normalize, tokenize text
  Layer 3 - DistilBERT: Transformer-based semantic understanding
  Layer 4 - Classification: 3-class output (Legitimate, Traditional Phishing,
            AI-Generated Phishing)
  Layer 5 - SHAP: Word-level explainability and feature attribution
  Layer 6 - Streamlit: Interactive web presentation

1.3 Key Innovations

  a) Semantic analysis (DistilBERT) instead of keyword matching
  b) Distinguishes AI-generated phishing from traditional phishing
  c) SHAP-based explainability shows WHY each message was flagged
  d) Nigerian financial sector focus with realistic banking communications
  e) Zero-cost deployment on HuggingFace Spaces free tier
  f) Training on Google Colab free GPU (T4)

3.3 Legitimate Communications (Class 0)

  Generated from templates mimicking real Nigerian bank messages:

  - Debit alerts: "Dear {customer}, a debit of NGN{amount} was made on your
    {bank} account {account} at {merchant} on {date}. Available balance:
    NGN{balance}. If not you, call {phone}."
  - Credit alerts: "Credit Alert: NGN{amount} received from {sender} into
    your {bank} account {account} on {date}."
  - Password reset notifications
  - KYC update reminders
  - Monthly statement notifications
  - ATM withdrawal alerts
  - Salary payment confirmations
  - Card expiry notifications
  - USSD banking instructions (*737#)
  - Pre-approved loan offers (legitimate)

  Banks referenced: GTBank, UBA, Access Bank, Zenith Bank, Fidelity Bank,
  First Bank, Moniepoint, PalmPay, Opay, Stanbic IBTC, Ecobank, Union Bank,
  Wema Bank, FCMB, Kuda, Carbon, Interswitch, Flutterwave, Paystack

3.4 Traditional Phishing (Class 1)

  Messages with poor grammar, excessive urgency, and suspicious URLs:

  - "URGENT!!! Your BVN has been BLOCKED. Click here to verify now: {link}"
  - "Your account will be SUSPENDED if you don't update your details now."
  - "Alert: NGN{amount} deducted from your account. If not you, click {link}"
  - "Your ATM card has been deactivated. Update your PIN here: {link}"
  - "Congratulations! You won NGN{amount} in our promotion. Claim prize: {link}"
  - "Your NIN must be linked to your BVN immediately or account will be frozen."

  Characteristics: ALL CAPS, multiple exclamation marks, misspellings,
  unfamiliar URLs (tk, ml, ga, cf, top, xyz domains), generic greetings.

3.5 AI-Generated Phishing (Class 2)

  Sophisticated messages with perfect grammar and psychological manipulation:

  - BVN-NIN Linkage Compliance Notice (impersonating CBN directive)
  - Account Suspension Notice (impersonating security operations center)
  - Unauthorised Transaction Reversal Notice (fake fraud alert)
  - KYC Update Final Notice (impersonating compliance department)
  - Debit Card Replacement Notification (fake security vulnerability)
  - CBN Beneficiary Account Verification (impersonating regulatory body)
  - Account Restriction Warning (fake regulatory compliance)
  - Refund of Duplicate Charges (fake audit finding)
  - Enhanced Security Verification (fake multi-factor authentication)
  - Tax Compliance Verification (impersonating FIRS)

  Characteristics: Professional formatting, official-looking subject lines,
  legitimate bank names, realistic URLs (bankname-portal.com, bankname-
  verify.com), authoritative tone, specific dates and reference numbers,
  corporate closing signatures.

3.6 Dataset Generation Script

  File: dataset/generate_dataset.py

  Key design decisions:
  - Procedural generation (no external API calls)
  - Reproducible (random seed = 42)
  - Configurable sample counts
  - Automatic deduplication
  - Realistic Nigerian context (Naira amounts, Nigerian names, local merchants)

4. PREPROCESSING PIPELINE
================================================================================

4.1 Text Cleaning (clean_text)

  Operations performed in order:
  1. HTML unescape (convert &amp; &gt; etc. to characters)
  2. Remove HTML tags (<br>, <p>, <div>, etc.)
  3. Replace URLs with [URL] token
  4. Replace email addresses with [EMAIL] token
  5. Remove non-alphanumeric characters (except .,!?;:'"()-)
  6. Collapse multiple whitespace characters
  7. Strip leading/trailing whitespace

4.2 Text Normalization (normalize_text)

  1. Convert to lowercase
  2. Collapse whitespace
  3. Strip

4.3 Duplicate Removal (remove_duplicates)

  - Removes rows with IDENTICAL text (exact-string deduplication)
  - Uses pandas DataFrame.drop_duplicates(subset=["text"], keep="first")
  - Keeps first occurrence of each unique string
  - Reports number of exact-string duplicates removed
  - IMPORTANT LIMITATION: This does NOT perform semantic or near-duplicate
    deduplication. Template-sibling AI-generated phishing samples that differ
    only in slot values (names, dates, amounts, URLs) will NOT be caught.
    For near-duplicate detection, use the validation/data_integrity.py script
    which provides character 3-gram Jaccard similarity and optional
    DistilBERT embedding cosine similarity checks.

4.4 DistilBERT Tokenization (tokenize_data)

  - Uses DistilBertTokenizerFast.from_pretrained("distilbert-base-uncased")
  - Max sequence length: 128 tokens
  - Truncation: enabled (messages longer than 128 tokens are truncated)
  - Padding: max_length (all sequences padded/truncated to 128)
  - Returns: input_ids, attention_mask as numpy arrays

4.5 Label Encoding

  - Scikit-learn LabelEncoder
  - Maps original labels (0, 1, 2) to encoded values
  - Supports inverse transform for interpretation

================================================================================
5. MODEL ARCHITECTURE: DISTILBERT
================================================================================

5.1 Why DistilBERT?

  - 66M parameters (vs BERT-base's 110M) = 40% smaller
  - 60% faster inference than BERT-base
  - Retains 95%+ of BERT's performance on downstream tasks
  - Can run on CPU for inference (no GPU needed for deployment)
  - Small enough for HuggingFace Spaces free tier (16GB RAM)

5.2 Model Architecture

  DistilBertForSequenceClassification(
    (distilbert): DistilBertModel(
      (embeddings): Embeddings(
        (word_embeddings): Embedding(30522, 768)
        (position_embeddings): Embedding(512, 768)
        (LayerNorm): LayerNorm(768)
        (dropout): Dropout(0.1)
      )
      (transformer): Transformer(
        (layer): 6 x TransformerBlock(
          (attention): DistilBertSelfAttention(768->768)
          (sa_layer_norm): LayerNorm(768)
          (ffn): FFN(768 -> 3072 -> 768, GELU activation)
          (output_layer_norm): LayerNorm(768)
        )
      )
    )
    (pre_classifier): Linear(768 -> 768)
    (classifier): Linear(768 -> 3)    # 3 output classes
    (dropout): Dropout(0.2)
  )

5.3 Configuration

  - Vocabulary size: 30,522 (English uncased)
  - Hidden size: 768
  - Transformer layers: 6
  - Attention heads: 12
  - Feed-forward size: 3,072
  - Max position embeddings: 512
  - Activation: GELU
  - Dropout: 0.1 (embedding/attention), 0.2 (classifier)

6.3 Training Loop (Manual, not Trainer API for transparency)

  For each epoch:
    1. Set model to train mode
    2. Iterate over training batches
       - Forward pass: model(input_ids, attention_mask, labels)
       - Compute loss
       - Backward pass: loss.backward()
       - Optimizer step: optimizer.step()
       - Scheduler step: lr_scheduler.step()
       - Zero gradients: optimizer.zero_grad()
    3. Set model to eval mode
    4. Iterate over validation batches
       - Forward pass (no gradients)
       - Collect predictions
    5. Compute metrics: accuracy, precision, recall, F1
    6. If F1 > best F1: save model checkpoint

7.4 Critical Review Findings and Caveats

  If the model reports a perfect 1.0000 score across all five evaluation
  metrics (Accuracy, Precision, Recall, F1-Score, and AUPRC) on the held-out
  test set, this should NOT be interpreted as evidence of guaranteed
  real-world performance.

  Likely cause — Near-duplicate contamination:

  The dataset is procedurally generated from a small number of templates
  (10 AI-phishing templates) with minor slot substitutions (names, dates,
  amounts, URLs, account numbers). The preprocessing pipeline only performs
  EXACT-STRING deduplication (Section 4.3), meaning semantically
  near-identical samples that differ only in slot values survive into both
  the training and test splits. This creates an information leakage scenario
  where the model memorises template-specific patterns rather than learning
  generalizable phishing indicators.

  Data-integrity validation:

  Before submission, run the validation script:

    python validation/data_integrity.py          # full check (with embeddings)
    python validation/data_integrity.py --fast   # n-gram overlap only

  The script implements three remediation checks:

    (i)   Near-duplicate check — Character 3-gram Jaccard similarity between
          train and test AI-generated phishing samples, plus optional
          DistilBERT [CLS] embedding cosine similarity. Reports the maximum
          similarity found.

    (ii)  Group-based split check — Extracts template skeletons by removing
          slot values (amounts, dates, names, URLs, phone numbers) and
          hashing the remainder. Reports how many template families span
          both train and test splits and the contamination rate.

    (iii) Confusion matrix text reproduction — The evaluation pipeline
          (evaluation/evaluate.py) now outputs the confusion matrix as both
          a PNG image and a bordered ASCII text table, so the
          zero-misclassification result can be verified directly.

  Recommended remediation steps before final submission:

    a) Run and report at least one of:
       - A near-duplicate check with the maximum similarity reported
       - A group-based re-split that keeps template families together
       - Evaluation on a genuinely external test set
    b) Reproduce the confusion matrix values as text, not only as an image
    c) Report the data-integrity validation results alongside the metrics

8. EXPLAINABILITY WITH SHAP
================================================================================

8.1 Why SHAP?

  SHAP (SHapley Additive exPlanations) uses game theory to compute the
  contribution of each input feature (word) to the model's prediction.
  It provides:

  - Local explanations: why a specific prediction was made
  - Consistent attributions: Shapley values are the only attribution method
    that satisfies consistency and local accuracy
  - Model-agnostic: works with any classifier

8.2 SHAP Algorithm for Text

  This project uses SHAP's Partition explainer with a text masker:

  1. The explainer creates masked versions of the input text (removing/
     replacing subsets of words)
  2. For each masked version, the model predicts the class probabilities
  3. The difference in prediction with vs. without each word is averaged
     over all possible subsets (efficiently approximated)
  4. Each word gets an importance value: positive = pushes toward predicted
     class, negative = pushes away from predicted class

8.3 PhishingExplainer Class (explainability/shap_explainer.py)

  Key methods:

  - explain(text, top_k=10) -> Dict
    Returns: prediction, confidence, probabilities, top_words,
    suspicious_words, explanation (natural language)

  - get_word_attribution(text) -> List[Dict]
    Returns: every token with its SHAP importance value

  - batch_explain(texts, top_k=10) -> List[Dict]
    Explains multiple texts

  Sample explanation output:

  "This email was classified as 'AI-Generated Phishing' with 94.3%
  confidence because it exhibits sophisticated social engineering
  techniques, professional yet manipulative language, and authority-based
  psychological persuasion. The words 'suspended', 'compliance',
  'immediately', 'validate', 'restricted' contributed significantly to
  the prediction."

8.4 Word Importance Scoring

  Each word receives a SHAP value where:
  - Large positive value: word strongly supports the predicted class
  - Large negative value: word contradicts the predicted class (supports
    a different class)
  - Near zero: word has minimal influence

  - NUM_CLASSES = 3
  - CLASS_NAMES = ["Legitimate", "Traditional Phishing", "AI-Generated Phishing"]
  - CLASS_MAPPING = {0: "Legitimate", 1: "Traditional Phishing", 2: "AI-Generated Phishing"}
  - EPOCHS = 5
  - BATCH_SIZE = 16
  - LEARNING_RATE = 2e-5
  - MODEL_SAVE_DIR, TOKENIZER_SAVE_DIR
  - RAW_DATASET_CSV
  - All directory paths

12.2 dataset/generate_dataset.py

  Generates 5000+ labeled samples across three classes. Contains:

  - BANKS: 20 Nigerian banks
  - FIN_TECH: 12 fintech companies
  - LEGIT_TEMPLATES: 18 legitimate message templates
  - TRAD_PHISH_TEMPLATES: 24 traditional phishing templates
  - AI_PHISH_TEMPLATES: 10 AI-generated phishing templates
  - Helper functions: _rand_amount, _rand_balance, _rand_date, _rand_bank
  - Main function: generate_dataset(n_legitimate, n_trad_phish, n_ai_phish)
  - CSV output with columns: text, label

12.3 preprocessing/preprocessing.py

  TextPreprocessor class with:

  - clean_text(text): Remove HTML, URLs, emails, special chars
  - normalize_text(text): Lowercase, collapse whitespace
  - remove_duplicates(df): Deduplicate DataFrame
  - tokenize_data(texts): DistilBERT tokenization
  - fit_label_encoder / transform_labels / inverse_transform_labels
  - preprocess_pipeline(df): End-to-end pipeline
  - preprocess_single(text): Single text for inference
  - create_preprocessed_dataset(): Convenience function

12.4 training/train.py

  Training pipeline:

  - compute_metrics(): Accuracy, precision, recall, F1, AUPRC
  - load_and_split_dataset(): 80/10/10 stratified split
  - tokenize_dataset(): Maps tokenizer over all splits
  - train_model(): Full training pipeline using HuggingFace Trainer API
  - Uses EarlyStoppingCallback (patience=3)
  - Saves best model by F1 score

12.5 evaluation/evaluate.py

  Evaluation pipeline:

  - load_model_and_tokenizer()
  - load_test_data(): Extracts 10% test split
  - predict(): Batched inference returning predictions + probabilities
  - evaluate_model(): Generates all metrics, plots, and reports
  - Outputs: classification_report.json, confusion_matrix.png,
    roc_curves.png, pr_curves.png, probability_distribution.png

12.6 explainability/shap_explainer.py

  PhishingExplainer class:

  - __init__(): Loads model + tokenizer, configures SHAP
  - _predict_proba(): Wrapper function for SHAP (list of strings -> probabilities)
  - _build_explainer(): Cached SHAP Partition explainer
  - explain(text): Full explanation with attribution
  - _generate_explanation(): Natural language explanation
  - get_word_attribution(): Per-token SHAP values
  - batch_explain(): Multiple texts

12.7 streamlit_app/app.py

  Streamlit web application:

  - load_explainer(): Cached model loader (st.cache_resource)
  - _fallback_analysis(): Keyword-based fallback (no model needed)
  - Sidebar: About, usage, supported institutions
  - Main: Text input, example selector, analyze button
  - Results: Prediction, confidence, risk level cards
  - Probability distribution bar chart
  - SHAP word importance chart
  - Suspicious indicators list
  - Highlighted text display

12.8 utils/visualization.py

  Matplotlib plotting utilities:

  - plot_confusion_matrix(): Raw + normalized side-by-side
  - plot_roc_curves(): Per-class + macro-average
  - plot_precision_recall_curves(): Per-class
  - plot_probability_distribution(): Per-class histograms

12.9 validation/data_integrity.py

  Data integrity validation script implementing three remediation checks:

  - check_near_duplicates(): Character 3-gram Jaccard similarity between
    train/test AI-generated phishing samples, plus optional DistilBERT
    embedding cosine similarity. Reports maximum similarity and threshold.
  - check_group_split(): Extracts template skeletons by stripping slot values,
    hashes the remainder, reports how many template families span both splits.
  - print_confusion_matrix_text(): ASCII text confusion matrix for direct
    verification of zero-misclassification results.
  - run_validation(): End-to-end pipeline combining all three checks,
    saves results to validation/integrity_report.json.

19. TROUBLESHOOTING
================================================================================

19.1 Common Errors

  ERROR: "cannot import name 'AdamW' from 'transformers'"
  CAUSE: Recent transformers versions moved AdamW to torch.optim
  FIX: Use "from torch.optim import AdamW" instead

  ERROR: "Unable to locate package #" (Spaces build)
  CAUSE: Comments in packages.txt
  FIX: Remove all comments and blank lines from packages.txt

  ERROR: "Missing configuration in README" (Spaces build)
  CAUSE: README.md missing YAML frontmatter
  FIX: Add YAML header with sdk, app_file, python_version

  ERROR: "UNEXPECTED keys" / "MISSING keys" (model loading)
  CAUSE: Normal - base model head replaced with classification head
  FIX: Ignore, or add transformers.logging.set_verbosity_error()

  ERROR: Model very slow (Spaces)
  CAUSE: SHAP on CPU is slow
  FIX: Reduce max_evals in app.py, or upgrade Spaces hardware

  ERROR: Space sleeping
  CAUSE: Free tier sleeps after 48 hours inactivity
  FIX: Normal - cold start takes 30-60 seconds
